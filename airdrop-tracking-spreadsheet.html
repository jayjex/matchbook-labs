Airdrop Tracking Spreadsheet

Airdrop farming fails on memory: three months after the work, nobody remembers which wallet did what on which date. This page prints one sheet that fixes that. A 12-row activity log with a write-in column for the wallet alias you used, a status circle per row, a season summary box for what you claimed and what you skipped, and the three scam patterns worth keeping in view while you work. The sheet records what you already did. It predicts nothing, and if an airdrop never lands, the sheet still did its job. For the listings side of bounty hunting, the Superteam Earn API reference maps the endpoints behind superteam.fun.

How to use this page: print the log at 100% scale (the site chrome drops out on paper), one row per action you take. Fill the wallet alias the moment you act, not from memory later. At the end of the season, complete the summary box: what you claimed, what you skipped and why. Keep the sheet somewhere private; it holds your activity history, so treat it like any other personal record.

The log: 12 rows, one page

Each row is one action. Project is the name as you know it. Action done is what you actually did, in a few words. Wallet / alias takes the nickname you gave that wallet, like burner-2, never anything secret. The status circle fills in with a pen: solid when the action is done, crossed out when you skipped it, left open while it waits.

Security reminders — read before you act

1. Never share a seed phrase or private key. Support staff, team members, admins: no legitimate role ever asks. A message that asks is a scam, whatever name or logo it carries.

2. Verify URLs yourself. Type the address or open your own bookmark. Links in DMs and comments stay unclicked until you have checked where they lead.

3. No real team DMs first. A message that opens with "airdrop verification" or "connect to claim" is a scam pattern regardless of who appears to send it.

This log organizes your own records. It does not create or guarantee any reward: projects set their own criteria, change them, or never run an airdrop at all.

Four opinions on keeping an airdrop log

  1. One sheet beats five tabs. Keep every campaign in one place. A log split across browser tabs, notes apps, and memory is a log you stop opening, and an unopened log answers nothing in month three.
  2. Write the alias while you act. Wallet nicknames evaporate from memory within weeks. The alias column only works if it gets filled at the moment of the action, which is why it sits next to the date instead of buried in notes.
  3. Dates make the record usable. Eligibility criteria tend to arrive with date windows attached. A row without a date cannot answer a single question about them, so the date column gets filled even when nothing else does.
  4. Log the skips too. "Skipped, and why" is the half of the record that shows where your time actually went. Three months later it is also the half that stops you from re-doing something you already decided against.

Honest limits

This page is personal record-keeping, not financial advice, and nothing on it predicts any project's plans. A tracker organizes history; it cannot create an allocation, and most activity by most people across most seasons earns nothing. Projects define their own criteria, publish them late, change them, or cancel. Anyone selling certainty about a specific airdrop is telling you something the tracker cannot.
