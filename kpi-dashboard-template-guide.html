KPI Dashboard Template: Build One in a Spreadsheet

A dashboard is one screen, five numbers, and a fixed update day. This guide covers picking the metrics, a text sketch of the layout, and a vanity-versus-action test. The examples track a web3 project because that is what our own spreadsheet pack tracks. Opinions are labeled, and the note at the end says what this page is not.

Pick the metric by the question it answers

A KPI earns its cell by answering a question you would otherwise guess at. Write the question first, then find the number that settles it. Five examples, one per template in our pack:

MetricQuestion it answersCadence
Net P/L per assetIs each holding above or below what I paid for it?Weekly, same day each week
Airdrop statuses (claimed / in progress)Which farms moved this week, and what are they worth?Weekly
Net ROI per DeFi positionWhich positions earn their deposit after rewards?Weekly or monthly
Bounty income by monthWhich platforms and task types pay?Monthly
Win rate and profit factorDoes the process make money after fees, over many trades?Monthly

Cadence is a promise about when the number gets typed in. Weekly metrics survive a weekly check; a daily metric dies the first busy week. If the number has not changed since the last update, type the same value anyway, so the history stays comparable.

The layout: three zones on one screen

Keep the whole dashboard visible without scrolling. Three zones do the work:

+--------------------------------------------------------------+
| HEADER                                                       |
| Month · date last updated · one line of context              |
+------------------------+------------------------+------------+
| METRICS                | METRICS                | METRICS    |
| 1 Net P/L per asset    | 2 Airdrop statuses     | 3 Net ROI  |
|   value + change       |   claimed / progress   |   percent  |
+------------------------+------------------------+------------+
| 4 Bounty income MTD    | 5 Win rate / PF        | NOTES      |
|   value + change       |   percent + ratio      | 3 lines max|
+------------------------+------------------------+------------+
  • Header. Month, the date you last typed numbers, one line about what changed. When a number looks wrong three weeks later, this line is the witness.
  • Metrics zone. The five rows from the table above, each as a value plus the change since the last update. The change carries more information than the raw number.
  • Notes zone. Three lines max, dated. What moved and the one-line why. Six months in, these lines explain spikes better than the numbers do.

Vanity versus action (opinions)

Every metric has an action version, the one that moves when you do something. Three comparisons from tracking our own numbers. These are opinions, not rules:

Feels like progressWhat it hidesThe action version
Total portfolio valueIt moves with the market while you do nothingNet P/L against your own cost basis
Airdrops farmed, countedThe count measures effortClaimed versus in-progress statuses, plus estimated value
Trades takenActivity reads as skillWin rate and profit factor after fees

Four opinions

  1. (Opinion.) Five KPIs max. One screen holds five numbers plus notes. Past that you are reading a report instead of tracking one, and the update day slips.
  2. (Opinion.) Same day, every update. Comparability beats precision. A rough number typed every Monday beats a careful number typed twice a month.
  3. (Opinion.) Enter the raw value, let formulas do the math. P/L, ROI, and win rate are computed columns. Hand-edited results make the history wrong quietly.
  4. (Opinion.) Keep the notes line alive. Every update gets one dated line in the notes zone. "Yield position dropped 40%, protocol changed reward rate" is worth more at review time than any chart.
