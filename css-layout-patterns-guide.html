CSS Layout Patterns (Free): Cheat Sheet for 6 Common Layouts

Most layouts are six patterns wearing different fonts. This free CSS layout cheat sheet lists each one with the exact CSS, the failure mode that eats your afternoon, and 4 opinions, each labeled as one. Every snippet is plain CSS mechanics, so it works in whatever stack you are holding.

How to use this page: find the row that matches the box you are trying to build, copy the CSS, and adjust the numbers. The patterns table: 6 layouts, exact CSS

Each row is one layout job. The CSS is the short version that works; the note names the failure mode people hit in real projects.

PatternThe CSSBreaks when
Centering one child.wrap { display: grid; place-items: center; min-height: 100dvh; }The child keeps its size; a second child stacks into the same cell. Use 100dvh, not 100vh, or the phone URL bar makes it jump.
Two-column (sidebar + main).layout { display: grid; grid-template-columns: 240px 1fr; }Long words or code in the 1fr column blow past it. The fix is minmax(0, 1fr), because 1fr alone will not shrink below content size.
Three-column card grid.cards { display: grid; gap: 16px; grid-template-columns: repeat(auto-fill, minmax(180px, 1fr)); }Wrong keyword: auto-fit collapses empty tracks and stretches the last items, auto-fill keeps their planned size. Pick by what an unfinished row should look like.
Sticky header.header { position: sticky; top: 0; z-index: 10; }An ancestor with overflow: hidden becomes the scroll container, so the header sticks inside a box that never scrolls. And sticky stops at its parent's edge; no travel room, no sticking.
Card row (horizontal scroll).row { display: flex; gap: 16px; overflow-x: auto; }Flex children refuse to shrink below their content, so one long word widens the whole row. min-width: 0 on the children lets the row scroll instead of overflow.
Footer pinned to bottombody { min-height: 100dvh; display: flex; flex-direction: column; } footer { margin-top: auto; }Short pages leave the footer mid-screen if min-height is missing or margin-top: auto is on the wrong element. margin-top: auto absorbs all free space above the footer.

Flex or grid? A short note

My rule (opinion, not a spec): reach for flex when the layout is one direction, a row or a column. Reach for grid the moment you need rows and columns to agree, or when you want gaps without margin-collapse surprises. Flex with flex-wrap can fake a grid, but the rows never line up by column, and that is exactly the look you do not want in a card wall.

Two mechanics worth memorizing either way: gap works in both and never collapses like margins do, and * { box-sizing: border-box; } is why your columns stop overflowing the moment the reset lands.

4 opinions, labeled as opinions

  1. Write the stacked layout first. (Opinion.) Get the single-column version right, then add columns at the breakpoint. Fixing a broken two-column layout on a phone is harder than widening a working one.
  2. Land the border-box reset before any pattern. (Opinion.) Under the default content-box, a 50% column with padding overflows its row and the bug looks like the grid's fault. One line of reset removes a whole class of "why is it 220px wide" debug sessions.
  3. Use gap, not margins, between items. (Opinion.) Adjacent vertical margins collapse into the larger one, so your spacing table lies to you. gap means the number you wrote is the space you get.
  4. Sticky needs a taller parent. (Opinion, born of a common bug.) A sidebar that sticks for zero pixels usually has a parent exactly its own height. Move the sticky element up a level or let the content column define the height, and it travels.
