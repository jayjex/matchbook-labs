Second Brain Setup Checklist: the Free One-Page Printable

Most notes systems fail in the first week, before any note-taking starts: no single inbox, folders invented on the fly, and a review step that never got scheduled. This page is the fix as a printable checklist. Sixteen checkboxes in four passes (capture, structure, review loop, archive) plus the three weekly review questions. Run it once during setup, roughly thirty minutes, and the system holds together after that. The steps name mechanics, so the checklist works in any notes app that has notes, folders, and search. How to use this page: print it, open your notes app next to it, and work top to bottom in one sitting. A checkbox only gets ticked when the "done means" line on that row is true, not when you intend it to be. Expect thirty minutes, most of it spent deleting the third folder you almost created.

The one-page setup checklist

Pass 1 - Capture: where new notes enter

☐One inbox note exists, and everything lands there first, before any folder. Done means: a new thought has exactly one entry point.
☐Phone capture reaches the same inbox. Done means: a test note saved on the phone is sitting in the inbox on the computer.
☐A daily note exists for today, and loose thoughts get dumped there by default. Done means: mid-task thoughts have a home that is not a sticky note.
☐Every new note starts with a date and a source line. Done means: rereading a note in a year tells you when it arrived and where it came from.

Pass 2 - Structure: where notes live after the inbox

☐Four folders exist: projects (has an end date), areas (ongoing upkeep), resources (reference you keep), archive (retired). Done means: a new note sorts into one of the four in under ten seconds.
☐One home note links to all four folders and to the inbox. Done means: opening the app starts at the home note, not at a folder list.
☐Naming is decided once: date-first or topic-first, pick one. Done means: the last ten notes you made follow the same pattern without thinking.
☐A move rule exists for the inbox: when notes leave, and who decides. Done means: the inbox has a scheduled empty-out time written somewhere real.

Pass 3 - Review loop: what keeps it alive

☐A weekly block is booked, same day and time each week, thirty minutes. Done means: it would survive a calendar check by someone else.
☐Inbox reaches zero during the block: file it, or delete it. Done means: no note has sat in the inbox for more than seven days.
☐Every live project holds a written next action. Done means: opening a project folder shows what to do first, on the project's own note.
☐Dead projects get moved to archive during the block, same day they are declared dead. Done means: the projects folder only contains things you would resume.

Pass 4 - Archive: what happens to finished things

☐The archive folder exists and is allowed to be messy. Done means: you stopped reorganizing it, and search does the finding.
☐A finished project moves to archive within a week of finishing. Done means: no completed project still sits in the active folder.
☐Daily notes older than a month get archived in one batch. Done means: the daily folder shows roughly a month of days, nothing older.
☐Search, not scrolling, is the archive's retrieval method. Done means: you found an archived note by searching one word from it.

The passes run in that order on purpose: capture first, because a system with no entry point collects nothing; structure second, because folders only make sense once notes arrive; review third, because structure decays without it; archive last, because you cannot archive what never got filed. The "done means" lines exist because half of setup checklists get ticked on intention. Yours get ticked on evidence.

The weekly review: three questions

Once the system runs, the weekly block asks three questions. Answer them on paper or in a review note; the point is writing the answer, not thinking it:

  1. What entered the inbox and never left? File it or delete it now, and notice whether the same kind of note keeps stalling.
  2. Which project has no next action? Write one on the project note, or move the project to archive. A project without a next action is a wish with a folder.
  3. What can be archived today? Finished, stale, or superseded. Moving it out is what keeps the active folders honest.

Four tips for keeping a notes system alive

Opinions, from running vaults the hard way. Take what holds up in your own week.

  1. One inbox, forever. The second inbox arrives politely, as "temporary" or "work stuff", and within a month it holds more than the first. When the urge comes, widen what the one inbox accepts instead of adding another.
  2. Tag sparingly. Ten tags per note feels organized on day one and reads like noise on day ninety. Two tags you actually reuse beat ten you invented once; search has quietly replaced most tagging anyway.
  3. Link before you file. A note linked from three places is findable three ways; a note filed in one folder is findable one way. When filing feels ambiguous, that is often the system saying a link would do the job better.
  4. Archive without guilt. An archive full of dead projects is a record of what you tried, and search makes it free to keep. Moving finished work out weekly is what keeps the live folders worth opening.

App-agnostic, on purpose: this checklist names mechanics (one inbox, four folders, a booked review), so it works in Obsidian, Notion, Apple Notes, Google Keep, or plain text files.
