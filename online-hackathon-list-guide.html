Most articles about finding hackathons online hand you five big directories and stop. This page treats the list as something you assemble and keep alive: five generic source types worth watching, a six-box fit checker to run before you commit a weekend, and four opinions on picking. No platform or event names appear anywhere, because directories change and the method carries over. A list starts the process; acceptance, judging, and outcomes belong to each event's organizers, and nothing here promises either.

Where to look: five source types

These are types of places, not specific sites. Each row says what to check before you trust the source for your list.

Source typeWhat to check
Developer communitiesChat servers and forums around programming languages and frameworks carry recurring event announcements. Check whether events repeat; a community that has run several online editions has a working format.
University programsCampus tech clubs and engineering faculties open some of their online editions to outside participants. Check the eligibility line first; some events restrict entry to enrolled students.
Open-source project ecosystemsLarger projects run community build events around releases and milestones. Check the project's own community hub rather than third-party summaries, which lag or garble dates.
Blockchain and protocol communitiesMulti-chain ecosystems publish event rounds and hacker houses on their community pages. Check which network each event targets, so the tooling you learn matches the chain you want to build on.
Local meetups with online branchesCity tech groups increasingly run hybrid editions. Check whether remote participants can submit and demo too; some hybrid events limit judging to the room, which changes what the weekend is worth to you.

Two or three of these sources, checked weekly, produce a steadier list than any single directory.

Fit-checker: six boxes before you commit

An event that fits someone else can still wreck your month. Print this sheet or copy it into your notes, one block per candidate event, and fill the write-in lines before registering.

Candidate event fit check

CheckFill in
Team size. Solo, pair, or squad? Write the headcount and which roles you still need. Some events match teams at kickoff; most expect you to arrive formed.write-in
Remote-ok. Online-only, or in-person with an online track? Write “online” or the city. Travel changes the cost of a weekend more than any entry fee.write-in
Prize-vs-learning. Write which one you are there for. Prize pools concentrate in a few projects; learning compounds for everyone who ships something.write-in
Time-zone overlap. Write the event's timezone and your workable build hours. An online event nine hours away turns into night shifts fast.write-in
Deadline distance. Write the registration deadline and the days left. Late registration plus timezone math is how weekends get lost before they start.write-in
Skill match. Write the one stack you would build on. If the event forces a framework you have never touched, the weekend becomes a tutorial instead of a build.write-in

Print this sheet (Ctrl+P / Cmd+P) and tick boxes with a pen, one column per candidate.

Four opinions on picking from your list

Opinions, not rules. Disagree freely.

  1. Pick one per quarter. Four committed weekends a year beat twelve “maybe” tabs. A quarter is long enough to ship something you would demo to a stranger, and short enough that your stack stays fresh. (opinion)
  2. Remote-ok beats prize pool for your first few. Early events are for reps: forming a team, scoping down, submitting on time. Entry fees and flights add up faster than prize odds pay back. (opinion)
  3. Arrive with the team written down. Team matchmaking at kickoff sounds friendly and eats the best build hours. The fit-checker's team-size box exists so the answer is settled before registration closes. (opinion)
  4. Keep the whole list in one dated file. Six browser tabs and three chat bookmarks will lose events. One file, one timezone, sorted by deadline — ours ships as CSV for this reason. (opinion)
