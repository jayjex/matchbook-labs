Dashboard Icon Set Guide — Free UI Icon Size & Consistency Tips

Free

A dashboard icon set fails quietly. One icon is 20 pixels and its neighbor is 24, one file is named with spaces, one corner is rounder than the rest, and the toolbar starts looking like five people shipped it. This guide collects the conventions that keep UI icons for dashboards consistent: four sizes that cover most surfaces, stroke versus filled, four consistency opinions, and a naming scheme that survives a folder of 200 files. It is generic UI knowledge, so it applies whether your icons come from us or from anywhere else.

Icon size conventions: 16, 20, 24, 32

Four pixel sizes cover most dashboard surfaces. They are conventions, not a standard; frameworks deviate, and that is fine. What matters is picking one size per context and never letting the same slot use two.

SizeWhere it usually shows upNotes
16pxFavicons, icons inline with body text, dense table rows, tree viewsThe smallest common size. A shape has to survive as a silhouette here.
20pxInput fields, buttons, breadcrumbs, compact navigationCommon default for form-adjacent icons in UI kits.
24pxToolbars, tab bars, card headers, standard navigationThe working size for most dashboards. If a set ships one size, it is usually this one.
32pxSection headers, empty states, feature grids, onboarding screensLarge enough for detail to read. Still UI, not illustration.

Check the grid of whatever framework your dashboard uses before locking sizes. The table above is the common ground, not a spec.

Four consistency tips

These are opinions, not rules. They match how the example pack was built, and they have survived contact with real toolbars.

  1. One stroke weight for the whole set. A 1.5px icon next to a 2.5px icon reads as two sources, even when everything else matches. Fifty icons at one weight sit next to each other without effort, which is what the README quote above promises in writing.
  2. One corner rounding. Corner radius is the detail your eye catches before you can name it. Pick a radius once, apply it to every shape that has corners, and stop deciding per icon.
  3. One accent color per group, not per icon. Color per icon turns a set into confetti. Grouping by color (indigo networks, teal DeFi, and so on) keeps variety without losing the row.
  4. Preview icons in the row where they will live. An icon that looks fine alone can wreck a toolbar. Line up the final row at final size before you ship; the row is the honest test.

Naming conventions for icon files

Three rules that keep a growing icon folder sortable:

  • Kebab-case. swap-arrows.png, never Swap Arrows.png. No spaces, no case-sensitivity surprises when files move between systems.
  • Size suffix. wallet-connect-24.png. The number is the pixel size the icon was drawn for, so future-you knows without opening it.
  • Category prefix. defi-liquidity.png, dev-rpc.png, wallet-hot.png. The group name first means an alphabetical sort is also a grouped sort.
