HUD Income Limits by County: What They Are, Where to Get Them, How to Join Them with FMR Data

HUD publishes two county-level number sets every year, and people mix them up constantly: Fair Market Rent (FMR) sets rent benchmarks, income limits set household income thresholds. This page is a guide to the income limits side: what 30/50/80% AMI means, which official files carry county-level values, and a worked approach for joining them with FMR data by county FIPS.

Scope note: we do not sell income limits data. Our product is the FY2026 FMR pack (51,895 ZIPs, 3,229 counties). Income limits come free from HUD directly, and this page links the official sources. The FMR pack is useful as the other half of the join: eligibility work usually pairs an income threshold with a rent number, and FMR is the rent number HUD itself uses.

FMR vs income limits: the two-table distinction

Both datasets come from HUD's Office of Policy Development and Research, both are updated annually, and both are published at metro/county geography. They measure different things and feed different parts of HUD programs.

Fair Market Rent (FMR)Income Limits
What it measuresRent: HUD's estimate of the 40th percentile gross rent (shelter rent plus utilities) for standard-quality units, monthly USDIncome: annual household income thresholds in USD, scaled by household size
LevelsOne number per bedroom size (0-4BR), per market area; Small Area FMRs add a per-ZIP figure in many metrosThree thresholds per household size: 30% of area median income (extremely low), 50% (very low), 80% (low)
Used forHousing agencies set Housing Choice Voucher payment standards from it (90% to 110% of FMR)Agencies and programs use it to determine whether a household falls inside an income band for eligibility screening
GeographyMetro FMR areas and nonmetro counties; SAFMRs at ZIP levelMetro areas and counties, with household size adjustments (1 to 8 persons)

AMI means area median income. HUD calculates it from American Community Survey data and publishes the limits already adjusted, so you rarely need to compute percentages yourself: the tables give you the 30/50/80% figures directly.

Where to find county-level income limits (official, free)

Named sources, none of which we are affiliated with:

  1. HUD User income limits page (huduser.gov/portal/datasets/il.html). The official release: income limits per metro area and county, per household size, as spreadsheets and PDFs. This is the primary source everything else derives from.
  2. HUD User API (huduser.gov/hudapi). Free account and API key. It exposes income limits endpoints alongside FMR endpoints, so you can pull both number sets programmatically instead of parsing spreadsheets.
  3. State housing finance agencies. For LIHTC and HOME program work, state agencies publish rent and income limit tables derived from the HUD figures, often restructured per program. Useful when a program applies its own adjustments; cite HUD as the underlying source.

All three trace back to the same HUD release. For anything with real consequences, the huduser.gov file is the one to keep open.

Sample approach: joining income limits with FMR data by county FIPS

Income limit files are keyed to county (or metro area) geography. Our FY2026 FMR county file is keyed by county name and state, and the ZIP file carries HUD area codes that embed the county FIPS for nonmetro areas, e.g. NCNTY01005N01005 contains FIPS 01005 (Barbour County, AL). That gives you two join paths:

Path 1, FIPS join (recommended): extract the 5-digit FIPS from the ZIP-level file's hud_area_code for NCNTY rows, build a county-to-FIPS table, then join with an income limits file that has a FIPS column. In pandas:

import pandas as pd

zip_df = pd.read_csv("fmr-by-zip-2026.csv")

# HUD area codes look like NCNTY01005N01005: chars 5:10 are the county FIPS
ncnty = zip_df[zip_df["hud_area_code"].str.startswith("NCNTY")].copy()
ncnty["fips"] = ncnty["hud_area_code"].str[5:10]
# area_name looks like "Barbour County, AL": strip the state suffix for the name join
ncnty["county"] = ncnty["area_name"].str.replace(r", [A-Z]{2}$", "", regex=True)
county_fips = ncnty[["fips", "state", "county"]].drop_duplicates()

# income limits file keyed by FIPS (from huduser.gov or the HUD User API)
il_df = pd.read_csv("income-limits.csv", dtype={"fips": str})
joined = county_fips.merge(il_df, on="fips", how="left")

# then bring in the county FMR rollup
county_df = pd.read_csv("fmr-by-county-2026.csv")
joined = joined.merge(county_df, on=["state", "county"], how="left")

Path 2, name join (fallback): metro FMR area codes do not map to a single county FIPS, so for metro areas match on normalized county or metro names plus state. Slower and more error-prone; watch for parish/borough/independent-city naming differences and strip strings like "HUD Metro FMR Area". We tested the extraction on the actual FY2026 files: 24,599 NCNTY ZIP rows reduce to 1,954 unique county keys, all with valid 5-digit FIPS. Joining those to the 3,229-row county rollup by state and county name leaves 13 unmatched rows, all Virginia areas where HUD lists several independent cities in one nonmetro area (for example "Alleghany County-Clifton Forge city-Covington city, VA HUD Nonmetro FMR Area"). Expect that handful and fix it by hand.

Whichever path you take, validate the join: 3,229 counties in the FMR rollup is your denominator, so a left join that keeps all county rows and reports unmatched counts will show you exactly which geographies need manual fixes.

Three research use cases for the combined tables

  1. Program eligibility research. With the 30/50/80% AMI columns next to county FMRs, you can describe the income-to-rent landscape of any county: where the 50% AMI threshold sits relative to what a 1BR FMR costs annually. Useful for researchers mapping which income bands face which rent levels. This is descriptive work on published numbers; actual eligibility determinations belong to the administering agency, which applies its own rules and documentation.
  2. County comparison. Sort counties by the gap between income limits and FMRs. Two counties can have similar income limits and very different FMRs, or the reverse. A ranked table of that spread is a standard first sheet in housing market reports and works in pandas, Sheets, or R with the join above.
  3. Rent-burden context. The common benchmark is that households spending more than 30% of income on rent carry a cost burden. FMR plus income limits lets you compute, for each county, what share of the 50% AMI figure a 2BR FMR represents. It is a rough contextual ratio built from two published government numbers, not a measure of any actual household.

Caveats worth knowing before you build on this:

Income limits change every fiscal year. HUD recalculates them annually, so any table you assemble has a vintage; keep the release year attached to every row.

They are program-specific. LIHTC, HOME, and voucher programs each apply their own derivations and adjustments on top of the HUD figures. A threshold that is correct for one program is not automatically correct for another.

Household size matters. Published limits run from 1-person to 8-person households, and comparing against the wrong column silently changes your answer by thousands of dollars.
